# Stitch同期

実装後の見た目を既存のStitchプロジェクトへ反映する。別プロジェクトを作成したり、
同期先の画面を推測したりしない。

## 固定の同期先

- プロジェクト: `ぱんだ.dev — Quiet Hokkaido Editorial`
- プロジェクトID: `4403079275156026689`
- デザインのsource of truth: `.stitch/DESIGN.md`
- 正規のデザインシステムasset: `49be9e8839944a5b83463f024e0ab9cb`

次の正規ルート対応だけを使用する。

| アプリケーションのルート | Stitch画面 | 画面ID |
| --- | --- | --- |
| `/` | `ぱんだ.dev — Homepage Redesign` | `ef7d62ca501d403c9288fc20b1d19711` |
| `/[slug]` | `ぱんだ.dev — Article Page` | `29bd480dd00e4446877d09e199621b06` |
| `/scraps` | `ぱんだ.dev — Scrap Index / Quiet Workshop Redesign` | `7ef1298ea6c742e6ac3191c942bc90db` |
| `/scraps/[slug]` | `ぱんだ.dev — Scrap with Code & Links` | `937ce44d2ad34cc49482e8b23787945d` |
| `/admin/scraps/new`, `/admin/scraps/[id]` | `ぱんだ.dev — Scrap Draft Workspace` | `456b9bc003c045aaa6715cdd5d07527b` |

`/admin/scraps`には正規画面がない。似た画面を選ばず、未同期として報告する。
`DESIGN.md`アップロード画面、別案のScrap Index、パンダイラスト画面は編集しない。

## 同期の要否を判断する

1. コードの差分を確認し、見た目が変わったルートを特定する。
2. API、サーバー動作、データ、テスト、見た目に影響しない文言、表示結果が同一の
   内部実装だけを変更した場合は同期しない。
3. レイアウト、スタイル、レスポンシブ動作、モーション、表示コンポーネントを
   変更した場合は、対応する画面を同期する。
4. `.stitch/DESIGN.md`または`src/app/globals.css`のsemantic Tailwind tokenを
   変更した場合は、先にデザインシステムを同期し、その変更が表示へ影響する
   正規画面を同期する。

## 書き込み前に同期先を検証する

Stitchへ書き込む直前に、プロジェクトと画面の読み取りツールを実行する。固定の
プロジェクトID、画面ID、画面名が一致することを確認する。同期先が存在しない場合や
名前が変わっている場合は停止して報告する。似た名前の画面で代用しない。

## 画面を同期する

1. `.stitch/DESIGN.md`、変更したUIコード、差分を読む。デスクトップとモバイルの
   違いや各状態を含め、実装後にユーザーから見える動作を把握する。
2. 実装後の見た目へ一致させ、変更していないコンテンツ、セクション、データ、
   デザインシステムを維持するよう、簡潔な`edit_screens`プロンプトを作る。
   ReactやTailwindの実装詳細ではなく、ユーザーから見える結果を記述する。
3. 直前のStitch読み取り結果に含まれる画面instanceをそのまま渡し、対応表にある
   画面だけを編集する。
4. 生成編集は一度だけ実行する。数分かかる可能性があるため、タイムアウトや接続
   エラーの後に同じ編集を再実行しない。後から画面を読み取り、成否を確認する。
5. 更新後の画面を読み取り、スクリーンショットを確認する。大きな差異が残る場合は、
   推測による追加編集を行わず報告する。

## デザインシステムを同期する

デザインシステムの定義自体を変更するときは`taste-design`スキルを使用する。
Stitchへ書き込む前に、`.stitch/DESIGN.md`とsemantic Tailwind tokenを一致させる。

1. プロジェクトのデザインシステム一覧から、固定した正規assetを探す。存在しない
   場合や表示名が`Quiet Hokkaido Editorial`でない場合は停止する。
2. Stitchから取得したデザインシステムobject全体を維持し、その`designMd`を
   `.stitch/DESIGN.md`の内容で更新する。別のデザインシステムassetや
   `DESIGN.md`画面を作成しない。
3. 固定プロジェクト内の正規assetだけを更新する。
4. 検証済みの正規画面のうち、変更の影響を受ける画面だけへassetを適用する。
5. デザインシステムと対象画面を再度読み取り、反映結果を確認する。

## 完了報告

プロジェクトID、使用した場合はデザインシステムasset ID、同期したルートと画面ID、
未同期範囲を報告する。Stitchツール、認証、正規ルート対応を利用できない場合は、
ローカル検証を別に完了させ、Stitch同期を実行できなかったことを明記する。
